# Stock scene actor boundary observer

The observer records the real `BioPawn.BeginAnimControl` and `BioPawn.FinishAnimControl` calls before and after their unchanged stock script execution. It does not invoke either event, move actors, alter inventory, reset animation, or replay a conversation. The records are private runtime diagnostics; they do not assert that an animation or gameplay behavior was verified.

Preparation checks the complete relocated script bodies (539 and 313 runtime bytes), every referenced object and name, exact event flags, original script executor, and the sole `InInterpGroup` object parameter (offset 0, size 8, `CPF_Parm`, class `Engine.InterpGroup`). The actor observer shares the existing script executor hook. All other script nodes retain the cheap stock forwarding path.

A callback is admitted only for a live `BioPawn` in the `SFXPawn_PlayerParty` hierarchy and the current native network world. Its scope comes from the current local controller and native owner connection, independently of possession, so temporary scene unpossession does not hide a boundary. The pawn actor channel scan result is recorded without rejecting the actor; a negative result means no unique validated result, which can include a missing channel or an unreadable/malformed channel list. The controller, world, network, camera and mode-manager scope is captured again after stock execution; lifetime and scope changes remain explicit.

Each boundary has a serial number, nesting depth and before/after records. The snapshots include actor/class/world and source-group identities; raw weapon selection; inventory manager; live weapon owner, instigator and inventory manager; mesh; the reciprocal Gestures module; the Matinee flag; its existing animation-set manager and signed gesture state; and signed current action IDs. Pointer cells distinguish a failed read, true null, and a readable value that is not a live object of the expected class. `CurrentCustomAction` and `CurrentPowerCustomAction` are integer IDs, not object pointers.

Animation-set and backup-set records contain the raw array header and a bounded pointer hash. Mesh sets sample at most 16 entries, backup sets at most 64, and the module list at most 128. Oversized samples, failed reads, malformed headers and unstable headers are explicit. Pointer hashes describe sampled membership only; they say nothing about pose or playback.

Only relevant party callbacks in the current owner scope consume the collection budget. Collection is limited to 64 callback pairs and four observed nested levels per process. All callbacks, including refusals and exhausted limits, call their incoming original executor exactly once with the original arguments. The observer preserves the error value seen by stock and returned by stock. The fixture covers forwarding, nesting, refusal, collection limits, error preservation and bounded array accounting. Actual cinematic playback still requires a manual gameplay session.
